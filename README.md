# Code-Optimizer-Grad-Project

An enterprise multi-agent system for autonomous source-code refactoring, complexity reduction, and sandboxed test validation.

This repository currently contains **Phase 1 of the repo analyzer**: filter and fingerprint. There is no user interface and no backend yet. Later phases of the same agent will be added as new modules inside `repo_analyzer/`, not as new top-level folders.

## Phase 1 Documentation

Phase 1 is the first of six phases of the repo analyzer. It takes the path of a software project folder and decides which files are worth analyzing. It returns the kept files, the skipped paths with a reason for each, and a fingerprint of exactly what was kept.
It is read-only. It only lists and reads files. It never runs the project, never calls a model, never follows symbolic links, and never opens anything that is not a regular file.
1. What the project includes
File	Purpose
repo_analyzer/phase1_filter.py	The walk and all skip rules (the main code).
repo_analyzer/models.py	Pydantic models for the output: FileEntry, SkippedEntry, FilterResult.
repo_analyzer/__main__.py	Command-line interface.
repo_analyzer/__init__.py	Public exports: filter_repo, FilterOptions, read_text, models.
tests/	helpers.py (builds tiny fake repositories) and test_phase1.py (the tests).
requirements.txt, pytest.ini	Dependencies (pydantic, pathspec, pytest) and test settings.

2. How it works
The function filter_repo() walks the repository from the root, one folder at a time, without recursion. Folders are judged before they are entered, so an ignored folder is recorded once and its contents are never listed.
1.	Judge each folder. The first matching reason wins: symlink, ignored_dir, virtualenv, vendor, nested_repo, gitignored, user_ignored. Otherwise the folder is entered.
2.	Judge each file by name. Symlink, matched by .gitignore, matched by .analyzerignore or --exclude, a binary extension (.png, .zip, .pyc ...), or a generated-file name (*_pb2.py, *.min.js ...).
3.	Judge each remaining file by content. The file is read once. It is skipped if it is not a regular file, is larger than 1,000,000 bytes, contains a NUL byte in the first 8 KB (binary), or says it was machine-generated in its first 5 lines ("DO NOT EDIT", "generated by" ...).
4.	Keep the rest. Each kept file is stored with its path, size, SHA-256 and extension.
5.	Compute the fingerprint. A SHA-256 over every kept file's path and content hash, sorted by path.
Ignore rules
•	Every .gitignore is honored, including ones in subfolders, with git's precedence: the file closest to the path wins, and a ! rule can bring a path back.
•	An optional .analyzerignore file in the repo root, plus any --exclude patterns, add your own rules.
•	Bad input never stops the scan: a malformed pattern is skipped with a warning, and an unreadable folder or a file name that is not valid Unicode is recorded as unreadable.

3. The output
The result is one FilterResult object. Its JSON form is result.model_dump_json().
Field	Meaning
root	Absolute path of the scanned repository.
files	Kept files, sorted by path. Each has path (relative, with / separators), size, sha256 and suffix.
skipped	Skipped paths with path, reason and is_dir. Folders end in /. Capped at 500 entries.
skipped_counts	Exact number of skipped paths per reason, even when the list is capped.
total_bytes	Total size of the kept files.
fingerprint	SHA-256 of the kept files. It changes if a kept file is edited, added or renamed, and does not change if a skipped file changes.
warnings	Notes such as "No files left after filtering" or an invalid ignore pattern.

Example
For a small project with src/app.py, tests/test_app.py, README.md, requirements.txt, a .git folder, node_modules, a .venv, a .gitignored log file, a PNG, a generated protobuf file and a symlink, the command-line summary is:
Repository : /tmp/demo
Kept       : 5 files, 92 bytes
Fingerprint: e118adcbb30740c37b746feb7848f152deb5fdd115729765a6d39857f918a79f
Skipped    : binary=1, generated=1, gitignored=2, ignored_dir=1,
             symlink=1, vendor=1, virtualenv=1

In the JSON result, files lists the five kept files and skipped lists the eight skipped paths, for example:
{ "path": "node_modules/", "reason": "vendor",     "is_dir": true  }
{ "path": "out/",          "reason": "gitignored", "is_dir": true  }
{ "path": "logo.png",      "reason": "binary",     "is_dir": false }
